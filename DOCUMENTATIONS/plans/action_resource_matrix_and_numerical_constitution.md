## 1. 行动资源矩阵 (Action Resource Matrix)

### 1.1 五大核心行动的输入/输出/系统定位

每个 Action 在系统中承担唯一的、不可替代的经济学角色。以下是经过架构评审后的最终矩阵：

| Action | 核心消耗 (Input Sink) | 核心产出 (Output Yield) | 系统级定位与架构契约 |
|--------|----------------------|------------------------|---------------------|
| **`FANG_SHI`** (坊市) | 时间 + **健康** | 金钱 (Money) | **生存下水道**。把命和时间贱卖换取房租的唯一底层 API |
| **`DENG_GAO`** (登高) | **巨量时间** | 健康 (Health) | **物理恢复阀**。用极高的时间成本换取身心机能恢复 |
| **`DU_ZHUO`** (独酌) | 时间 + 健康 + 金钱 | 全情绪清空 (State Reset) | **系统级 GC**。透支肉体来强制重置精神状态栈 |
| **`BAI_YE`** (拜谒) | 时间 + 金钱 | 官场进度 (Official Progress) | **纵向跃迁**。用通货资源填补垂直阶级的里程碑阈值 |
| **`JIAO_YOU`** (交游) | 时间 + 少量金钱 | 社交进度 (Social Progress) | **横向拓扑**。用时间解锁社交图谱的战争迷雾 |

### 1.2 间接依赖闭环 (Indirect Dependency Loop)

系统设计的核心不在于直接写死关联逻辑，而在于数值自身驱动玩家行为：

```
拜谒(吞金) → 缺钱 → 坊市(卖血换钱) → 缺血 → 登高(烧时间回血)
```

**无需任何硬编码 `if/else`，数字本身会把玩家在名利场、血汗工厂、终南山之间来回驱赶。**

## 2. S/M/L 资源汇率刻度体系

### 2.1 基准锚定 (The Physical Constants)

在设计任何具体数值之前，必须先死钉系统的底层分母：

| 常量 | 值 | 含义 |
|------|----|------|
| Max Health | 100 | 跌破 30 触发疾病，跌破 0 死亡 |
| Base Rent (生存税) | 50 Money / 旬 | 旬末强制扣除 |
| 一旬 AP | 10 Time | 每旬可支配的行动点数 |

### 2.2 S/M/L 刻度定义

所有资源消耗和产出必须严格使用以下三级刻度，禁止裸写具体数字：

| 刻度 | 占比 (相对满血的倍率) | 示例 (Money) | 示例 (Health) | 设计意图 |
|------|----------------------|-------------|--------------|---------|
| **S (Small)** | 10%~15% | ~20 | ~15 | 钝刀子割肉，单次感知不强 |
| **M (Medium)** | 30%~40% | ~50 | ~30 | **警示阈值**，连续 2 次逼近生存红线 |
| **L (Large)** | 50%~60%+ | ~100 | ~50 | 救命/搏命量级 |

### 2.3 量化行动矩阵 (Quantified Action Matrix)

将 S/M/L 刻度应用到五大 Action 的精确数值：

| Action | Time | 核心消耗 | 核心产出 | 架构锐评 |
|--------|------|---------|---------|---------|
| `FANG_SHI` | 4 天 | Health **-M** (~30) | Money **+L** (~100) | 牺牲 1/3 血条换两旬房租。连续 3 次触发濒死 |
| `DENG_GAO` | 5 天 | 纯时间 | Health **+L** (~50) | 烧半旬时间回血，是坊市卖命后的唯一恢复手段 |
| `DU_ZHUO` | 1 天 | Health **-S** (~15) + Money **-S** (~20) | 全情绪清空 | 廉价慢性毒药。一天喝完，但天天喝必破产 |
| `BAI_YE` | 3 天 | Money **-M** (~50) | Official Progress **+M** | **不直接扣血，但榨干现金，逼玩家去坊市卖血** |
| `JIAO_YOU` | 2 天 | Money **-S** (~20) | Social Progress **+S** | 细水长流的社交税 |

### 2.4 跨周期汇率验证

**命题："3 次拜谒 ≈ 需要 1 次登高来弥补"**

验证链：
1. 3 次拜谒 = 3 × 50 = **150 Money** 消耗
2. 玩家需要执行 **2 次坊市** (2 × 100 = 200 Money) 来填补
3. 2 次坊市 = 2 × 30 = **60 Health** 消耗
4. 玩家必须执行 **1 次登高** (+50 Health) 把血线拉回安全区

> ✅ **闭环验证通过。** 数值自洽，无需任何硬编码依赖。

## 3. TTB 数值设计方法论

### 3.1 核心概念

**TTB (Turns To Bankrupt)** 是生存类 CRPG 数值设计的核心方法论。不要凭空捏造数值——必须先锚定系统的流失底线，然后逆向推导所有收益。

### 3.2 三步逆向推导法 (SOP)

```
Step 1: 锚定基准税 (Anchor the Tax)
  系统设定：每旬必扣 50 Money + 自然老化 10 Health

Step 2: 设定死亡周期 (Set the TTB)
  玩家什么都不干时，期望 N 旬后破产
  
Step 3: 逆推核心动作收益 (Reverse Engineer Yields)
  如果希望"打工 1 次苟活 2 旬" → 坊市产出必须 = 2 × 50 = 100 Money
  如果希望"连续打工 3 次病倒" → 每次坊市扣 100/3 ≈ 33 → 取 M 级 ~30 Health
  登高回血必须 ≥ 30（能补回一次坊市损耗）→ 取 L 级 ~50 Health
```

### 3.3 数值调优原则

- **前期绝对不改数值。** 所有数值写入全局配置常量（如 `GlobalConfig.gd` 或等效的 JSON 配置表）。
- **白盒测试 10 圈后再微调。** 只有当你发现"永远饿不死"或"三天暴毙"时，才去调配置表。
- **禁止在事件 CSV/JSON 中硬编码具体数值。** 详见 [第 5 章：事件库数值宪法](#5-事件库数值宪法)。

## 4. 诗词-网关解耦架构决策

### 4.1 问题诊断

当前实现中，**拜谒的入口强制要求玩家递交一首诗**，这导致：

- 玩家行为异化：为了推进主线，被迫变成"没有感情的写诗机器"
- 诗词从高级 Modifier 系统降级为低级 Fuel（门票）
- 意象坍缩引擎（V3）的神圣"灵魂审判感"沦为流水线计件工作

### 4.2 Phase 1 决策：选项对比

| 维度 | 选项 A：网关强耦合 | 选项 B：事件内分支结算 |
|------|-------------------|---------------------|
| **描述** | 点击拜谒 → 检查是否有诗 → 有则扣除诗，允许进入；无则弹回 | 点击拜谒 → 只扣 Time+Money 进门 → 事件内 Option 分歧 |
| **网关纯度** | ❌ 被污染。资源转换器混入了高级资产检查 | ✅ 纯粹。网关只做资源置换 |
| **玩家体验** | 写诗变成计件工作 💀 | 写诗 = 囤积战略核武器 |
| **叙事合理性** | 前期无才华无诗 → 卡关 | 前期砸钱硬拜（低效屈辱），后期带诗暴击（高效高光） |
| **架构评审** | **绝对禁止** ❌ | **强烈推荐** 🤓☝️ |

### 4.3 最终方案：解耦后的两层模型

```
┌─────────────────────────────────────────────┐
│  Action Layer (网关层)                        │
│  拜谒入口：只扣除 Time + Money（打点费）         │
│  契约：有钱有时间就能进门，不检查任何载荷         │
└──────────────────┬──────────────────────────┘
                   ▼
┌─────────────────────────────────────────────┐
│  Event Layer (事件内分支)                     │
│  Option 1: 卑躬屈膝奉承                        │
│    → 消耗尊严 + 少量 Progress                  │
│  Option 2: "递上一首干谒诗"（需持有已完成的诗）   │
│    → 消耗诗 + 结合品质产出巨量 Progress + 赏赐   │
└─────────────────────────────────────────────┘
```

### 4.4 诗词作为战略资产

- 诗词是**具象化的可囤积道具**，不是即时结算的瞬时数值
- 写诗完成后，诗保留为物理实体，可带入任意兼容事件作为高级筹码
- 诗的品质（T1~T3）决定在事件中的产出倍率

## 5. 事件库数值宪法

### 5.1 核心原则：基准绝对守恒，乘数动态扭曲

> **Constitution First Principle: Constant Base, Dynamic Distortion**

在任何 Event Variant（事件变体）中：
- 资源置换的**基准值**绝对刚性，全局唯一定义
- 叙事多样性只能通过**乘数 (Modifier)** 施加扭曲

### 5.2 宪法第一条：禁止硬编码数值

**死罪写法：**
```json
{"target": "HEALTH", "value": 50}
```
→ 每次调数值都要改几百个事件，地狱级维护成本 💀

**正确写法：**
```json
{"target": "HEALTH", "value": "GLOBAL_DENG_GAO_BASE"}
```
→ 在全局配置中统一定义 `GLOBAL_DENG_GAO_BASE = L级 ≈ 50`，一处改动全局生效

### 5.3 宪法第二条：乘数扭曲机制 (Multiplier Distortion)

叙事多样性不来自不同的 Base 值，而来自玩家当前的**特质 (Trait)** 或**情绪**对基准值的乘数扭曲。

```
最终收益 = GLOBAL_BASE × ∏(Trait Multipliers) × ∏(Emotion Modifiers)
```

示例：
- 玩家有 `旷达·高` → 登高回血 = `GLOBAL_DENG_GAO_BASE × 1.3`
- 玩家有 `忧郁` → 独酌效果 = `GLOBAL_DU_ZHUO_BASE × 0.7`

### 5.4 宪法第三条：事件库只能引用，不得定义

所有 Event Config JSON (如 `tools/bai_ye_honeymoon_config.json`) 中：
- ✅ 可以引用：`"cost": "BAI_YE_MONEY_COST"` 
- ❌ 不得定义：`"cost": 50`
- ✅ 可以声明乘数：`"modifier": "KUANGDA_HIGH_MULT"`
- ❌ 不得裸写乘数值：`"modifier": 1.3`
