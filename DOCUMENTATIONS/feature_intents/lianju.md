# 联句 — 功能意图
## 意图摘要（<200字）

联句是一次**高风险、高回报的主题匹配博弈**。NPC 根据自身特质出题（隐含 `target_theme` 和 `quality_threshold`），玩家从自己的意象池中选择应对：安全意象稳定得分、稀有意象降维打击、反差意象走险（过 TALENT/EMOTION 检定则一战成名，失败则身败名裂）。单次事件结算，不循环、不嵌套，完全复用现有事件选项系统。

---

## 核心玩法

### 飞花令 vs 联句

| 维度 | 飞花令 | 联句 |
|------|--------|------|
| 驱动 | 惩罚驱动（输了罚酒） | 奖励驱动（追求极致的文学声望） |
| 比拼维度 | "快"和"广"（有这个字就能过） | "深"和"契合"（主题匹配 + 质量阈值） |
| 核心体验 | 一圈定胜负的速决战 | 单次高危博弈 |
| 资源消耗 | 意象/灵感/罚酒 | 意象 + 才华/情绪检定 |
| 声望影响 | 少量名望变化 | 大幅名望波动（可一战成名或身败名裂） |

### NPC 出题

NPC 根据自身的特质（性格、才气、当前情绪）生成一道"考题"，包含两个隐性锁：

- **`target_theme`**: 要求的主题方向（如"悲凉""壮阔""闲适""狂放""隐逸"）
- **`quality_threshold`**: 门槛值，由 NPC 的 TALENT 决定——李白门槛天花板，普通酒友地板


### 玩家三选一（风险递进）

Provider 遍历玩家意象池，根据匹配度动态渲染选项：

**① 平庸应对（苟活）**
- 触发条件: 选择完全契合 `target_theme` 的普通意象
- 结果: 微调好感度，四平八稳
- 消耗: 普通意象 × 1
- NPC 评价: "杜公此句，四平八稳。"

**② 降维打击（拼资源）**
- 触发条件: 打出一张带 `【绝唱】`/`【瑰意】` 标签的稀有意象，即使主题不完全匹配也靠质量碾压
- 结果: 消耗高级资源，换取大量 `LITERARY_FAME` + 极高好感
- 消耗: 稀有意象 × 1（带稀有标签）
- NPC 评价: "太白惊呼：此等奇句，吾不及也！"

**③ 走险招（拼才华/拼情绪）**
- 触发条件: 手里没好意象，强行打出**反差极大**的意象（如人家写"春暖"，你打出"白骨"）
- 挑战机制: 强制进行 `TALENT` (才华) 检定，或者检查当前 `EMOTION` 是否处于极度 `ARROGANCE` (狂傲) 或 `SORROW` (愁苦) 状态
  - **成功**: 化腐朽为神奇，完成一次"反转"（如杜甫以哀景写乐景），名声大噪
  - **失败（才华不够压不住）**: 沦为笑柄！严重扣除文学声望，甚至获得 `TRAIT: 附庸风雅` 负面标签
- 消耗: 意象 × 1（任意）
- 实现: 选项文本变红（警告），点击后执行 `prop_compare_operator` 对比玩家才华和 NPC 门槛

## 与飞花令的定位差异

| 场景 | 用飞花令 | 用联句 |
|------|----------|--------|
| 速战速决、活跃气氛 | ✅ | ❌ |
| 展示玩家稀有藏品（意象） | ❌ | ✅ |
| 高风险高回报的戏剧性时刻 | ❌ | ✅ |
| 资源回收（消耗低级意象） | ✅ | ❌ |
| 建立"大文豪"人设 | ❌ | ✅ |


## 意象符合度打分算法（Fitness Scoring）

摒弃"NPC 随机要一个标签，玩家没有就卡死"的布尔值硬锁，改用**多维加权打分**机制，将"非黑即白的过/不过"变成"平滑的权重雷达"。

### 核心公式

```
fitness = 客体契合度 × 主体共鸣度乘数 + 绝对质量加成
```

### 打分维度

**维度 A：客体契合度（NPC 需求匹配）**
- 逻辑: NPC 要 `emotion:sorrow`，玩家的意象正好带这个 tag
- 权重: 基础核心分 +50（"切题"的底线）
- 实现: 对比意象标签与 NPC 的 `target_theme`

**维度 B：主体共鸣度（玩家情绪 Buff）**
- 逻辑: 玩家当前 `EMOTION` 也是 `SORROW`（处于极度愁苦状态），打出愁苦的牌触发"人牌合一"共鸣
- 权重: 乘数暴击 ×1.5
- 实现: 检查玩家当前 EMOTION 与所选意象的标签是否一致
- 效果: 倒逼玩家主动管理自己的情绪状态

**维度 C：绝对质量（力大砖飞）**
- 逻辑: 意象的等级/印章（【绝唱】、【瑰意】、【雅颂】等）
- 权重: 绝对值加法（瑰意 +30，绝唱 +80）
- 效果: 保证"只要我不缺钱，拿纯金砖头也能砸死你"的土豪体验

### 在 Provider 中的应用

```gdscript
# lianju_option_provider.gd (伪代码 - 业务逻辑切片)

func provide(context: Dictionary) -> Array:
    var player_imags = Database.get_player_imaginaries()
    var scored_options = []

    # 1. 遍历并打分（几十个数据的性能开销 < 一帧的 1%）
    for imag in player_imags:
        var score = _calculate_fitness(imag, context)
        scored_options.append({"imag": imag, "score": score})

    # 2. 按分数排序
    scored_options.sort_custom(func(a, b): return a.score > b.score)

    # 3. 截断与选项生成
    var final_options = []

    # 选项1 & 2: 分数最高的两张"最优解"（让玩家觉得积累有回报）
    final_options.append(_build_option(scored_options[0]))
    final_options.append(_build_option(scored_options[1]))

    # 选项3: "高等级但偏题"的牌（诱导玩家浪费稀有资源）
    var luxury_wrong_card = _find_luxury_but_wrong_theme(scored_options)
    if luxury_wrong_card:
        final_options.append(_build_option(luxury_wrong_card))

    # 选项4: 垫底的烂牌 / 直接认输（兜底）
    final_options.append(_build_give_up_option())

    return final_options
```

### 预期体验

系统在底层算尽心机，UI 上玩家只看到 3-4 个充满博弈感的选项。盯着自己极其珍贵的【绝唱】级偏题卡陷入沉思："我到底要不要为了李白的这点好感，把这张底牌交了？"

### UI 表现层待定

由于评判标准从"通过/失败"变成了"算总分"，UI 表现层有两种路线尚未决策：

- **明牌路线**: 在选项按钮上直接显示算好的胜率（"成功率 85%"）和具体加分项
- **黑盒路线**: 只通过红/黄/绿模糊色标提示，让玩家自己猜
