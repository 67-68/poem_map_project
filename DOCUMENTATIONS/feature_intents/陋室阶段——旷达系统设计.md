三大礼赋时间点

草... 😨 你终于开始关心主线大版本更新的 Timecode（时间戳）了？

你以为杜甫在历史上献《三大礼赋》是那种按部就班的投简历、走官方审批流吗？不，那是一次极其典型的**侧信道攻击 (Side-Channel Attack)**，是他试图越过网关直接修改底层数据库的疯狂举动！

启动 **[历史/政治沙盘推演]** 与 **[架构师]** 插件。让我们像复盘一次严重的系统越权事件一样，来拆解 751 年的这场"三大礼赋"风波：

### 1. 历史溯源：这是一次怎样的系统越权？

- **发生时间：** 历史上是 **公元 751 年（天宝十载）正月**。当时唐玄宗搞了一次服务器级别的全量大活儿----连续举行三个国家级大典（祭祀太清宫、太庙、南郊）。
- **他是怎么绕过李林甫的？**

李林甫把持着当时的尚书省和吏部，这就是盛唐的 **API API Gateway（通用网关）**，普通人所有的 `POST /api/career/apply` 请求都会被他无情地 `403 Forbidden`（比如 747 年的"野无遗贤"）。

但杜甫极其聪明，他利用了国家大典期间系统开放的一个**临时、未记录在案的"进献祥瑞"的后门接口**。他没有把赋交给任何官员，而是通过极高风险的渠道（历史记载是直接献给皇帝的行在/相关大典接管机构），直接把数据 `Push` 到了最高权限拥有者----玄宗（Root 节点）的面前 🤓☝️。

- **李林甫为什么没有反对？**

这正是整个事件里最黑色幽默的地方 🤣！玄宗在庆典上看到这三篇极尽华丽的赋，龙颜大悦。皇帝的"开心"是**最高级别的硬件中断 (Hardware Interrupt)**，李林甫作为软件层的网关，根本不敢当场抛出异常去扫皇帝的兴。

### 2. 约束的悖论：李林甫的"延迟垃圾回收"

你以为越过李林甫直达天听，杜甫就赢了吗？天真！李林甫虽然拦不住皇帝看文章，但他控制着整个官僚系统的**回调函数 (Callback Function)** 💀。

玄宗看完很高兴，下令："让这小子去考个试看看（命待制集贤院）。"

考试通过后呢？李林甫的系统接管了后续流程。他没有给杜甫分配任何实际的官职（没有赋权），而是把杜甫塞进了一个名为"集贤院待制"的**死循环 (Infinite Loop) 线程**里挂起。杜甫就在这个待命池里干巴巴地等了整整四年，一直等到李林甫死，甚至等到安史之乱爆发，他还在跑这个没有 return 的循环 😭。

### Phase 1: 决策隔离 (游戏落地时机与机制)

既然我们摸清了底层逻辑，在游戏中设定《三大礼赋》的出现时机，你有两条架构路径：

#### 方案 A：严格的历史时间锁 (Hardcoded Time-Trigger)

- **机制：** 决议必须在 750 年底亮起，751 年初强制执行/过期。
- **代价/工时：** 开发成本低。但如果玩家在 750 年时刚好处于极度破产状态，或者根本没有点出相关的文化属性，系统强推这个决议会导致他们瞬间 Core Dump（游戏崩盘）。
- **评价：** 适合作为极其硬核的历史模拟器，容错率极低。

#### 方案 B：状态与时代的复合约束 (State-Driven Event)

- **机制：** 将决议的触发条件改为：`Date >= 749 && Date <= 753 (李林甫死前) && (Player.State == '逢迎' || Player.State == '钻营') && Player.Desperation > Threshold`。
- **代价/工时：** 需要在后台维护一个"绝望值/内耗值"的计数器。
- **评价：** 极度推荐 🤓☝️！这就意味着【三大礼赋】不再是一个干瘪的历史任务，而是玩家在长安当了几年狗、经历了高适离去的刺激、内耗到快要发疯时，**主动**抓住的最后一根赛博稻草。虽然历史上是 751 年，但在游戏里，它可以是玩家心理防线崩溃的那一年。

**结论：** 如果我是你，我会选择 **方案 B** 作为底层逻辑，但会在 UI 层将 751 年的"国家三大盛典"作为一个环境 Buff 广播出来，暗示玩家："系统后门开了，这是你唯一能绕过右相府的机会，你要不要赌上所有身家去发这个 Payload？" 😡

既然这注定是一场"耗尽所有资源、直达天听，最后却被李林甫无情挂起在待命池"的虚无操作。那么在玩家倾家荡产完成大礼赋、收到玄宗夸奖的兴奋劲还没过的时候，你打算用一个什么样的 UI 交互或者资源结算界面，来表现这种"无限期等通知，最后生生把人拖垮"的终极折磨感？

### 1. 【登高】网关：专属的"打分选择器"与 GC 机制

登高是没有外部 NPC 干扰的纯粹精神活动，这里是【管线 B (单线) / 管线 C (对立分支)】的绝对主场。

- **狂客 (高旷达) 的天人合一：**

    - _获取方式：_ **主动兑换**。你消耗巨量体力爬山。

    - _算子结算：_ 触发 `prop_add(name=TRANQUILITY; val=30)`，同时清空所有负面情绪。使用打分选择器，必定掉落最高级的名篇意象（如：`[一览众山小]`）。
- **逢迎 (中旷达) 的短暂喘息：**

    - _获取方式：_ **选择残渣**。

    - _算子结算：_ 触发 `prop_add(name=SORROW; val=15)`。掉落中规中矩的伤感意象。
- **钻营 (低旷达) 的冰冷俯视：**

    - _获取方式：_ **纯场景渲染 (管线 A)**。

    - _算子结算：_ 复用之前的野心意象和事件


### 2. 【交游】网关：清流圈的"复合维度"修罗场

这里全是人情世故，必须调用【管线 D (复合维度：场景 × 情绪 × NPC)】。

- **事件 4：理想主义的共振 (狂客 × 清流)**

    - _获取方式：_ **情绪守卫分支模式**。必须检定 `ARROGANCE ≥ 20`。

    - _算子结算：_ 获得 `[狂傲]` 类意象，清流好感度暴增。
- **事件 5：薛定谔的清高 (逢迎 × 清流)**
	- 增加/减少少量burnout和其他坏情绪，增加少量灵感
- **事件 6：功利的同行者 (钻营 × 清流)**

    - _获取方式：_ **选择残渣**。你极其功利地在酒局上套取情报或拉投资。

    - _算子结算：_ 你的行为极其卑劣，底层隐式扣除 `[名望]`，并强制注入 `prop_add(name=BURNOUT/SORROW; val=20)` 的负面情绪。你拿到了人脉，但带回了一身的精神内耗 😭。

### 1. 架构死穴：玩家意图 (Agency) 与成本 (Cost) 的错位

在游戏设计中，**UI 上的入口按钮，代表的是玩家主动缔结的资源契约 (Resource Contract)。**

- **【交游】(主动发起)：** 玩家点击这个按钮，潜台词是："我今天要把我宝贵的 `[精力]` 和 `[时间]` 作为 Request Payload 传出去，我期望得到一个确定的 Response（维护关系/打探情报）。" 此时如果发生事件，那是**业务的正常流转**。
- **【坊市】(被动偶遇)：** 玩家点击这个按钮，潜台词是："我出门买菜（消耗少量资源），我知道这里是公域流量池，我接受任何 Random 算子的调度。" 此时如果遇到王维，这叫**系统级的中断/惊喜 (Interrupt/Exception)**。

如果你把它们放在一个库里靠 Tag 区分，你在配表的时候绝对会精神分裂：偶遇王维需要扣除拜访的礼物钱吗？偶遇王维算作今天的社交行动额度吗？**你试图用一个底层数据结构，去兼容两种完全不同的经济模型和玩家意图 💀。** 别干这种蠢事，老老实实把它们拆成两个独立的 Repository（事件池），互不干涉，这才是真正的干净 😡。

### 1. 架构解耦：IAM 权限 vs. JWT 载荷

在你的系统里，这两套设定的本质完全不同：

- **【旷达状态】(高/中/低)：这是你的内部心理权限 (IAM Role)。** 它决定了你"愿意干什么 / 能干什么"。它管的是你的 Action Gateway（行动网关）。你是低旷达，你就能点下"写黑材料陷害别人"的按钮；你是高旷达，这个按钮就会被灰掉（Disable）。它对标的是你内心的底线。
- **【社交标签】(清客/知音)：这是你的外部历史资产 (JWT Payload / Database Record)。** 它记录了你过去行为在别人眼里留下的"客观社会印记"**。它管的是别人**"怎么对你"。
