## 意图摘要（<200字）

将所有中文文本从数据源和 UI 层提取为翻译 Key，通过 Godot `TranslationServer` + `Util.tr_and_resolve()` 管道统一翻译。支持多语言（zh/en/ja）。数据源层（CSV/.tres）的文本字段使用 `[域]_[子模块]_[语义标识]` 命名空间 Key 替代，UI 层亦然。翻译表为 Godot 兼容的 CSV 格式（`keys,zh,en,ja`），存放于 `data/1_core_rules/translations/`。

---

## 铁律一：严格的命名空间前缀契约

**绝对禁止裸 Key。** 如 `Start`、`Apple`、`Error` 这种无上下文边界的 Key，在跨场景复用时会引发歧义灾难。

强制命名规范：

```
[领域/类型]_[子模块/场景]_[具体语义标识]
```

规范范例：

| Key | 含义 |
|-----|------|
| `UI_MENU_START_BTN` | 主菜单开始按钮 |
| `ITEM_APPLE_DESC` | 苹果道具描述 |
| `ERR_NET_TIMEOUT` | 网络超时报错 |
| `DLG_NPC_TAISHAN_01` | 泰山道士对话第一句 |

CSV 事件层命名：

```
事件 title:   EVT_{UUID}_TITLE      例: EVT_TEST1_TITLE → "长安酒馆奇遇"
事件 desc:    EVT_{UUID}_DESC       例: EVT_TEST1_DESC
选项 desc:    EVT_{UUID}_OPT_{N}    例: EVT_TEST1_GIVE_MONEY_OPT
```

## 铁律二：绝对禁止代码拼字

**`tr("You killed ") + str(count) + tr(" enemies")` 是死罪。**

不同语言语序不同，拼接会导致翻译语法灾难。

唯一合法做法：使用带命名参数的格式化插值。

翻译表内文本使用 `{param_name}` 占位符：

```
UI_KILL_STAT: 你击杀了 {count} 个 {enemy_type}
```

业务代码只负责整串取出后注入变量（`Util.tr_and_resolve` 已内置此机制）。

## 数据流

```
CSV 数据源 (.csv) ──→ 中文 → Key 替换 ──→ DSLParser ──→ .tres (含 Key)
                                                              │
UI 层 (.tscn/.gd) ──→ 中文 → Key 替换 ──────────────────────┤
                                                              │
                    ┌─────────────────────────────────────────┘
                    ▼
          Util.tr_and_resolve(text, context, instance)
                    │
                    ├── _is_constant_key(KEY) → tr() → TranslationServer
                    │       │
                    │       └── keys.csv → .zh.translation (Godot import)
                    │
                    └── resolve_template() → 占位符 {param} 插值
                    │
                    ▼
              最终显示文本
```
