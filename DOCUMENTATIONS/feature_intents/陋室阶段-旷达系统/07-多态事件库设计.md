# 07 — 多态事件库设计：八大屈辱维度 × 六大网关

> 本文档定义「多态事件库」——陋室期最核心的事件生成系统。基于 **8 种屈辱维度 × 6 个网关** 的正交矩阵，每个组合通过 `emotion_pair` 情绪对硬绑定实现 per-option 意象打分。

## 1. 概述

### 1.1 为什么要一个「多态事件库」？

陋室期的叙事核心是**制度性羞辱**——不是单次的打击，而是结构性的、重复的、每天以不同面貌出现的碾压感。

为了实现这种「同一个底层困境，每次以不同面貌出现」的效果，需要一个**正交事件生成系统**：

- **维度 A（屈辱类型）**：定义「你在哪个方面被羞辱」——才华被物化？阶级被碾压？同侪超越你？
- **维度 B（网关）**：定义「羞辱发生的场景」——市场里被轻视？宴会上被无视？考试中被淘汰？
- **每个 combos**：生成一个独立的事件叙述，但共享一套选项结构和情绪意象路由。

### 1.2 设计目标

| 目标 | 说明 |
|------|------|
| **正交性** | 每个屈辱维度独立于场景，可任意组合 |
| **情绪一致性** | 每个屈辱维度硬绑定一对情绪（branch_A / branch_B），确保选项意象逻辑自洽 |
| **场景合理性** | 通过 `linked_value_ids` 剪枝无效组合（没有「科举」×「在权贵家敲门」这类矛盾组合） |
| **叙事多样性** | 8 × 6 = 48 原始组合 → 31 有效组合，每组 3 个选项 × 3 条提示 = 279 条叙事产出 |
| **意象自动化** | per-option 自动调用 `pick_best_image()` 选择最高亲和度意象 |

- **✓** = 有效组合（31 个）
- **✗** = 被 `linked_value_ids` 剪枝（17 个）

### 2.2 数据流

```text
管线启动 load_config_from_json("duotai_humiliation")
    │
    ├── 维度展开: expand_combinations()
    │   ├── humiliation_type (8值) ← 每个值携带 emotion_pair tag
    │   └── gateway (6值) ← linked_value_ids 剪枝 → 31 combos
    │
    ├── LLM 批量生成事件描述 (31 combos × 3 prompts each)
    │
    ├── 选项 Hook 4: emotion_pair_imagery_plugin
    │   ├── 读取 choice.pair_role → 确定目标情绪
    │   ├── 读取 combos 中 humiliation_type 的 emotion_pair tag
    │   ├── lookup emotion_pairs[pair_id].{pair_role}.emotion
    │   └── extract_image_pool(gateway) → pick_best_image(target_emotion)
    │
    └── 输出: {combo, description, options[{text, imagery_add, ...}]}
```

## 5. 组合剪枝 (linked_value_ids)

### 5.1 剪枝原理

不是所有屈辱类型在所有网关中都合理。例如「科举」不会发生在「在权贵家门口敲门」的场景中。为了避免 LLM 生成逻辑矛盾的事件，使用 `linked_value_ids` 机制：

- 每个 `humiliation_type` 维度值的 `linked_value_ids` 列出其合法的 `gateway ID` 列表
- 管线在 `expand_combinations()` 时自动剪枝：`humiliation_type(A) × gateway` → 只保留 gateway ID 在 A.linked_value_ids 中的组合

### 5.2 剪枝矩阵

```text
humiliation_type \ gateway   坊市  交游  拜谒  独酌  登高  奉召
─────────────────────────────────────────────────────────────
才华物化  (pair_rebellion)     ✓    ✓    ✓    ✗    ✗    ✓
审美强暴  (pair_rebellion)     ✓    ✓    ✓    ✗    ✗    ✗
残羹冷炙  (pair_survival)      ✓    ✗    ✓    ✓    ✗    ✗
廉价劳力  (pair_survival)      ✗    ✓    ✓    ✗    ✗    ✗
```

## 6. 情绪对硬绑定系统 (emotion_pair)

### 6.1 动机

旧版管线（类型 C/D）在维度中有一个独立的「情绪维度」来驱动意象选择。但多态事件库的每个 combo 已经是 2D 正交，不能再加第三个情绪维度（会导致维度爆炸）。

解决方案：**把情绪编码到 humilation_type 维度值的 tags 中**，通过 `emotion_pair:` 前缀声明该维度值绑定的情绪对 ID。

### 6.2 机制

```text
humiliation_type 维度值
    │
    ├── id: "talent_commodified"
    ├── tags: ["emotion_pair:pair_rebellion", ...]
    │
    └── → 解析器通过 tag 前缀 "emotion_pair:" 提取 pair_id
         → 在 EventPipelineConfig.emotion_pairs 中查找
         → 根据 option.pair_role 获取目标情绪
         → 调用 pick_best_image(target_emotion)
```

### 6.3 配置结构

```python
# tools/config.py

class EmotionPairBranch(BaseModel):
    emotion: str = ""    # 情绪ID，如 "ARROGANCE", "TRANQUILITY"
    desc: str = ""       # 人类可读描述

class EmotionPairConfig(BaseModel):
    branch_A: EmotionPairBranch     # → 狂客选项的情绪目标
    branch_B: EmotionPairBranch     # → 钻营选项的情绪目标
    fallback: EmotionPairBranch     # → 逢迎选项的情绪目标

# EventPipelineConfig 新增字段
emotion_pairs: dict[str, EmotionPairConfig]
```

## 7. Per-option 意象选择 (emotion_pair_imagery_plugin)

### 7.1 插件定位

实现 [`EventPromptPlugin`](../../../tools/config.py) 接口的 Hook 4 (`get_option_result_extras`)，在 `apply_dimension_imagery: false` 模式下接管意象选择逻辑。

### 7.2 选择流程

```text
emotion_pair_imagery_plugin.get_option_result_extras(combos, choice)
    │
    ├── 1. 读取 choice.pair_role
    │     ("branch_A" | "fallback" | "branch_B")
    │     空字符串 → 跳过（无意象绑定）
    │
    ├── 2. 解析 combos 中 humiliation_type 的 emotion_pair tag
    │     提取 pair_id (e.g. "pair_rebellion")
    │
    ├── 3. 在 self._emotion_pairs 中查找 EmotionPairConfig
    │
    ├── 4. 获取目标情绪: pair_cfg.{pair_role}.emotion
    │     e.g. emotion_pair_imagery_plugin 获取 狂客 → ARROGANCE
    │
    ├── 5. extract_image_pool(combos, scene_dim_id="gateway")
    │     从当前 gateway 维度值的 tags 中提取意象白名单
    │
    ├── 6. pick_best_image(pool, target_emotion, image_dict, min_score=30)
    │     按情绪亲和度打分，选择最高分意象（≥30分）
    │
    └── 7. 返回 DSL: "imagery_add(name=<image_id>)"
```

### 7.3 DSL 输出示例

```text
# 狂客 (branch_A) 在 才华物化×坊市 中选到 ARROGANCE 意象
imagery_add(name=ink_stone)

# 逢迎 (fallback) 在 阶级霸凌×拜谒 中选到 FATIGUE 意象  
imagery_add(name=ruined_wall)

# 钻营 (branch_B) 在 残羹冷炙×独酌 中选到 AMBITION 意象
imagery_add(name=high_tower)
```

### 7.4 与旧版的区别

| 方面 | 旧版 (imagery_acquisition_plugin) | 新版 (emotion_pair_imagery_plugin) |
|------|----------------------------------|-----------------------------------|
| 触发时机 | 每 combo 一次（所有选项共享同一意象） | 每 option 一次（每个选项独立选意象） |
| 情绪来源 | 维度中的独立情绪维度 | 屈辱维度的 emotion_pair tag + option.pair_role |
| 适用场景 | 通用类型 C/D 事件 | 多态事件库（陋室期专属） |
| 配置标志 | `apply_dimension_imagery: true` | `apply_dimension_imagery: false`（禁用旧版） |

## 8. 选项结构

### 8.1 三选项范式

| 选项 | `pair_role` | 旷达状态 | 情绪目标 | 特性 |
|------|------------|---------|---------|------|
| `opt_kuangke` | `branch_A` | 高旷达（狂客） | 正向情绪 | 有风骨但可能付出代价 |
| `opt_fengying` | `fallback` | 中旷达（逢迎） | 中性偏负 | 妥协但安全 |
| `opt_zuanying` | `branch_B` | 低旷达（钻营） | 负面情绪 | 功利但必显示极致谦卑+求财心 |

### 8.2 钻营约束

钻营选项（低旷达）虽然追求功利，但**必须遵守以下约束**：

- 主角表现出极端的谦卑和求财欲望（"只要给钱，什么都行"）
- **绝对禁止**背叛朋友或出卖良心（杜甫的底线）
- 配置中通过钻营维度的 `narrative_constraint.negative_examples` 严格约束
- 示例：「我可以为您的诗集写一篇跋文——署名自然是您的」vs ❌「我可以出卖王兄的秘密」

### 8.3 配置示例

```json
{
  "id": "opt_kuangke",
  "name": "狂客之选",
  "pair_role": "branch_A",
  "prompt": "这是【狂客（高旷达）】的选择。选项展现出主角的风骨和傲气...",
  "accept_influence": ["ARROGANCE"],
  "result_template": "prop_add(name=ARROGANCE; val=5)\nprop_add(name=MINOR_RESOURCE; val=10)"
}
```

## 12. 扩展指南

### 12.1 新增屈辱维度

1. 在 `event_base_config_duotai_humiliation.json` 的 `humiliation_type` 维度新增一个值
2. 设置 `tags` 中包含 `emotion_pair:<pair_id>` 标签
3. 设置 `linked_value_ids` 为合法的 gateway ID 列表
4. 在 `emotion_pairs` 中新增或复用已有情绪对
5. 在沙盒文件中新增对应 combos 的 prompt 模板

### 12.2 新增网关

1. 在 `gateway` 维度新增一个值
2. 设置场景 tags（用于意象池白名单）
3. 在目标屈辱维度的 `linked_value_ids` 中更新合法性
4. 在沙盒文件中新增所有屈辱类型 × 新网关的 prompt 模板

### 12.3 新增情绪对

1. 在 `config.py` 中确认 `EmotionPairConfig` 模型可用
2. 在配置文件的 `emotion_pairs` 段新增 pair
3. 在屈辱维度值中引用新 pair_id
4. 确保 `option_features` 中的 `pair_role` 指向正确分支
